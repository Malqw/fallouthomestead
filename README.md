# Homestead Builder (статическая версия — GitHub Pages / Netlify)

Тот же инструмент (Поселение / Отряд / Склад), что и серверная версия (`homestead-server`) и
исходный `fallout_homestead_1.08.html`, но полностью статический — без сервера, без аккаунтов,
без бэкенда. Один HTML-файл + папки с картинками карточек и музыкой, которые можно захостить
где угодно как обычный сайт (GitHub Pages, Netlify, Vercel, да хоть просто открыть файл локально).

## Как это работает

- **Данные хранятся в браузере** (`localStorage`), на конкретном устройстве. Никакого входа,
  никакого сервера — заходишь и сразу работаешь. Открыл с телефона — там будут свои отдельные
  данные (это НЕ синхронизируется между устройствами).
- **⭳ Скачать JSON / ⭱ Загрузить JSON** (кнопки в Отряде) — так переносишь сохранение между
  устройствами или делишься отрядом с другом: скачал файл на одном устройстве, загрузил на другом.
- **🃏 Карточки** — у юнитов, предметов, перков и модов есть кнопка просмотра настоящей карточки
  (покрытие ~100%). Картинки лежат в `cards-web/` (сжатые WebP, ~33 МБ), подгружаются только по
  клику, не все разом.
- **🖨 Печать состава** — раскладка ростера картинками карточек вместо текста (только бойцы с
  отметкой «Миссия»). Все настройки размеров — в коде, см. функцию `printSquadRoster()`.
- **🎵 Радио Пустошей** — список треков зашит в код (`MUSIC_TRACKS` в начале секции музыки),
  файлы лежат в `music/`. Чтобы добавить песню: положить mp3 в `music/` и дописать
  `{file, title}` в массив `MUSIC_TRACKS` вручную (в отличие от серверной версии, тут нет
  бэкенда, который сам сканирует папку).

## Локальный запуск для проверки

Открыть `index.html` напрямую двойным кликом почти сработает, но браузеры блокируют некоторые
вещи для `file://` (в частности `fetch`/`Audio` в некоторых случаях) — надёжнее поднять любой
локальный статический сервер в этой папке, например:

```
python -m http.server 8000
```

и открыть `http://localhost:8000`.

## Деплой на GitHub Pages

1. Создать новый репозиторий на GitHub, запушить в него содержимое этой папки.
2. В настройках репозитория — Settings → Pages → Source: выбрать ветку (обычно `main`) и папку `/ (root)`.
3. Через пару минут сайт будет доступен по адресу `https://<твой-юзернейм>.github.io/<имя-репозитория>/`.

## Деплой на Netlify

1. Тот же GitHub-репозиторий подключить в Netlify (New site from Git → выбрать репозиторий).
2. Build command оставить пустым, Publish directory — `/` (корень репозитория) — собирать тут
   ничего не нужно, это готовая статика.
3. Netlify сам выдаст адрес вида `<имя>.netlify.app` и будет пересобирать сайт при каждом пуше.

## Синхронизация с другими версиями

Этот проект — независимый форк на момент переноса всех фич из `homestead-server` (карточки,
мобильный UX, печать состава). Он НЕ обновляется автоматически при правках `homestead-server`
или исходного `fallout_homestead_1.08.html` — при необходимости перенести фичу сюда, попроси явно.

Чего тут нет (сознательно, раз нет сервера):
- аккаунтов/логина — данные привязаны к браузеру, а не к пользователю;
- именных сохранений на сервере — вместо них скачивание/загрузка JSON;
- автосписка треков — плейлист жёстко задан в коде.
